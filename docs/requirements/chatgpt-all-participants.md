# 通常モードのChatGPT参加と音声設定簡略化 requirements

- status: requirements-approved
- version: 2
- owner: gpt-5.6-sol operational coordinator
- adjudicator: gpt-6-astra
- created: 2026-09-07

## Problem and users
ChatGPT音声参加者は現在、講師の収録モード中だけ起動する。通常の自習室では同じルームの全参加者がChatGPTと会話できない。また、Windowsの通信入力やChatGPTのマイクが物理マイクへ戻ると、ホストの声だけ届いてリモート参加者の声が届かない。

## Outcomes and success measures
- 講師が通常モードからChatGPTを有効化し、同じLiveKitルームの人間全員のマイク音声をChatGPTへ届け、返答を全員が聞ける。
- 2回目以降は検証済みの配線を1回の操作で起動できる。
- 初回または配線変更時は、アプリ内で変更可能な項目を一括適用し、Windows/ChatGPT側で残る操作を誤認なく案内する。

## Scope
### In scope
- 通常モードの講師ダッシュボードにAI参加者の有効化、停止、設定、状態表示を追加。
- AI音声のpublishと人間音声ミキサーを収録モードから独立させ、現在ルームに追従。
- 通常グリッドにAIタイルを参加者として表示し、全参加者が返答を聞ける。
- 既存の推奨配線一括適用と検証済み指紋を通常モードから利用可能にする。
- Windows向け診断/復旧スクリプトを、VoiceMeeter配線と録音の既定通信デバイスまで1回の実行で修復・再診断できるようにする。

### Non-goals
- OpenAI APIへの切替、API課金、ChatGPTアカウント操作。
- ブラウザからWindows設定やChatGPTアプリ内部の明示的マイク選択を直接変更したと偽ること。
- AI音声の自動文字起こし、司会、発話者選択。
- この機能の実装完了と同時の本番公開。

## Functional requirements
- FR-001: 講師だけが通常モードでAIを有効化・停止・設定できる。受講生には操作権限を与えない。
- FR-002: AI有効中は収録モードの有無にかかわらず `useAiParticipant` を稼働させ、現在ルームの予約AI participant接続からChatGPT音声を1トラックだけpublishする。
- FR-003: ChatGPT入力には同ルームの人間音声を各人一経路だけ含める。リモート人間マイクはアプリのミキサーで送出する。ローカルマイクは推奨VoiceMeeter構成ではIN1→B1の直接経路を使いアプリ混合を無効にし、直接経路のない構成ではアプリ混合を使う。AI音声、画面共有音声、Unknown、ループバック入力を除外し、参加・退出・再publish・ルーム移動に追従する。
- FR-004: AI返答は通常の参加者グリッドに名前・状態付きの専用タイルとして表示され、同ルームの全参加者へ聞こえる。AIが無効・切断ならタイルと音声トラックを除去する。予約AI接続の導入後も、AI返答の再生は各リスナーにつき一経路、明示開始した録画への入力は各録画につき一経路とする。ホストは直接モニターと予約AI接続の購読再生を重複させない。録画はregistryの直接トラックと予約AI接続の受信トラックを重複混合しない。異なるMediaStreamTrack IDでも同一のAI音声として扱い、再publish・再接続・録画中のAI開始／停止に追従する。
- FR-005: 通常モードの講師UIに「ChatGPTを参加」「停止」「音声設定」を置き、接続準備中・アプリ音声接続中・設定不足／エラーを区別する。過去の疎通確認日時は別表示し、指紋一致だけで「会話可能」「全参加者との疎通確認済み」と表示しない。
- FR-006: 新しい検証記録が現在の音声ソース、通話マイク、送出先、ローカルマイク経路と一致し、対象デバイスが列挙される場合、参加の1操作でアプリ側接続を開始する。送出先なし、旧指紋のみ、自己ループ確認のみでは全参加者向け検証済みと扱わず設定パネルへ誘導する。録画とChatGPT音声会話は開始しない。初回または検証失効時は、設定パネルの明示操作「未検証でテスト接続」から往復確認用の接続を開始できる。接続に必要なデバイスと経路の条件、講師認証・在籍・予約identityの競合規則は通常接続と同じとする。テスト接続中は未検証と表示し、接続成功や自己ループ確認だけでは往復確認を記録しない。ChatGPT音声会話の開始は利用者が行い、リモートのみの音声による往復確認に合格した場合だけ現在の指紋へ確認日時を保存する。失敗・中止・設定変更時は未検証を維持する。
- FR-007: 設定パネルの「推奨をまとめて適用」はAI音声ソース、通話マイク、ChatGPT送出先、構成に対応するローカルマイク経路を適用する。VoiceMeeter推奨構成では `sendLocalMic=false` とする。検証記録は版、配線指紋、ブラウザ配線確認、自己ループ確認、リモートのみの音声による往復確認、確認日時を区別する。旧指紋は設定値を保つが新しい全参加者向け検証済みへ自動昇格しない。一括適用は項目ごとに変更前値・要求値・再取得した変更後値・結果（変更済み／変更不要／失敗／未実行）を表示する。読み取り不能は不明として扱う。途中失敗時は成功項目を保持して部分成功と表示し、検証記録を失効させる。再実行は実値を再取得し、要求値と異なる項目だけを適用する。
- FR-008: Windows復旧スクリプトの明示的な修復モードは、対象デバイスを名前ではなく列挙結果から一意に解決し、VoiceMeeterのIN1/B1/Virtual Input B1と、録音の既定通信デバイスを推奨値へ設定し、設定後の実値を再取得して結果を返す。変更前に全対象を解決し、曖昧・欠落時は一切変更しない。適用開始後の失敗は残りの変更を中止し、各項目の変更前値・要求値・再取得した変更後値・結果を返して非ゼロ終了する。適用済み項目は保持し、再実行では一致項目を変更不要として扱う。部分成功を修復完了または疎通確認済みとは表示しない。
- FR-009: ChatGPTアプリ内部のマイクが既定通信デバイスを追従しない場合、UIとスクリプトは「自動設定完了」と表示しない。ChatGPT Classicで `Voicemeeter Out B1` を選ぶ手順と完全再起動を示し、最後にリモート参加者だけが話してChatGPTが応答する確認を要求する。音声ソース、通話マイク、送出先、ローカル送出経路の変更、対象デバイス欠落、検証仕様変更、ユーザー申告の外部設定変更で記録を失効する。観測不能な外部変更を検知できるとは表示しない。
- FR-010: AIを停止、講師が退出、ルームを移動、LiveKitが切断、または予約AI接続が置換された場合は、ミキサー、hidden audio、AI capture/publish、監視、registry登録を停止し、遅延処理で再publishしない。停止対象はアプリが作った経路であり、VoiceMeeter直接経路とChatGPT音声セッションは継続する。この制約を停止操作付近に示し、完全停止にはChatGPT側ミュートまたは音声会話終了を案内する。終了した処理世代の非同期完了は、接続・publish・registry登録・状態更新を再開しない。移動処理中の予定された切断は、ルーム移動の規則に従う。

  | イベント | 停止後の状態・再開条件 |
  |---|---|
  | 明示停止・講師退出 | 有効化意図を解除し、再開しない。 |
  | 講師の明示的ルーム移動 | 移動前の経路と処理世代を終了し、有効化意図を保持する。移動先への講師接続完了後、現在の設定・デバイス・在籍・予約AI接続の空きを確認して、新しい処理世代で再開する。条件不成立なら停止状態で理由を表示し、明示操作を待つ。 |
  | 人間側または予約AI側のLiveKit接続喪失（再接続開始を含む） | 現在の経路と処理世代を終了し、自動再取得しない。人間側の接続復旧後もAI再開は講師の明示操作を要する。 |
  | 予約AI接続の置換 | 経路と処理世代を終了し、競合を表示する。自動再取得しない。 |
  | 収録モードの開始・終了 | AIの処理世代と有効化意図を維持する。 |
- FR-011: 収録モードへ出入りしてもAI有効状態を不意に変更せず、既存の収録レイアウト、AI録音トラック登録、タブ音声重複防止を維持する。
- FR-012: 同ルームのAI音声publishには一つの予約participant identityを用い、LiveKitが保持する接続とトラックを稼働状態の正本とする。通常開始は既存稼働を検出すると拒否する。同時開始時はLiveKitの同一identity規則に従い、置換された側は音声処理を停止して競合を表示し自動再取得しない。再取得は明示操作に限る。先着取得やroom metadataの原子的更新は保証しない。

## Non-functional requirements
- NFR-001: AI無効時の既存通話・録音・収録挙動を変えない。
- NFR-002: AI音声をChatGPT入力へ戻す再帰ループを構造的に作らない。失敗途中のaudio要素やノードを残さない。
- NFR-003: 操作ボタンと状態はキーボード操作・スクリーンリーダーで識別でき、モバイル講師UIでも利用できる。
- NFR-004: 設定API、診断出力、状態metadata、ログには音声内容を保存・送信しない。必要なLiveKit音声配信、ChatGPT入力、利用者が明示開始した既存ローカル録画は対象外とする。本機能は録音を自動開始しない。AI接続トークンは講師認証と対象ルーム在籍を検証し、操作講師identityをサーバーセッションから決める。予約AI接続は自身のmetadata更新権限を持たない。
- NFR-005: AIの所有・稼働判定はroom metadata更新と独立させる。studio更新でAI接続や判定を失わない。metadataは表示情報だけに使い、排他の正本にしない。旧クライアントは通常通話を継続できる。

## Constraints and dependencies
- Windows + ChatGPT Classic + VoiceMeeter + VB-CABLEの既存構成を対象とする。
- WebアプリにはOS設定・ChatGPT内部設定を直接変更する権限がない。Windows修復はリポジトリ同梱スクリプトのローカル実行として提供する。
- Next.js 16.2.4の関連ローカルdocsを実装前に読む。

## Security, privacy, migration, rollback, and observability
- AI owner変更APIは講師認証、ルーム在籍、revision、owner整合性を検証する。
- クライアント申告のowner identityを信用しない。
- エラーは設定UI付近に表示し、consoleに秘密・音声内容を出さない。
- 機能はAI無効を初期値とし、問題時はAIを停止すれば既存通話へ戻る。

## Assumptions
- 「全参加者」は、AIを有効化した講師と同じLiveKitルームでマイクをpublishしている人間全員を指す。
- ChatGPTの音声会話自体はユーザーがChatGPT Classicで開始する。

## Unresolved questions
- ChatGPT Classic内部の選択デバイスを安定して外部から変更できる公開手段は確認できないため、明示選択が残る場合は初回手動操作とする。

## Requirement acceptance criteria
- RAC-001: `npx tsc --noEmit` と対象eslintがexit 0。
- RAC-002: ブラウザ結合テストで設定不足、旧指紋、送出先なし、自己ループのみ、ChatGPT内部入力だけ変更の各ケースが誤って疎通済み表示にならず、新検証済みでは1操作接続、停止、収録モード往復ができる。検証記録がない初回状態から、設定パネルのテスト接続、リモート往復確認、確認日時保存、停止、次回の1操作接続まで到達できる。失敗・中止・設定変更では次回の検証済み接続を許可しない。
- RAC-003: 2人以上の模擬RemoteParticipantについて人間音声のみ接続され、AI/画面共有/Unknownが除外される。直接経路あり／なしでローカル経路が重複せず、停止後の経路状態が定義と一致する。
- RAC-004: 未認証・受講生・未在籍のAIトークン発行を拒否する。同時開始、studio更新交差、停止後再取得、owner退出、ルーム移動、再接続、遅延処理について、予約identityに複数稼働が残らず置換側が停止し自動再取得しない。FR-010の状態表の各遷移を検証し、特に移動先競合、移動中の明示停止、接続復旧、旧処理世代の遅延完了が規定どおりに動くことを確認する。
- RAC-005: Windows診断をdry-runで実行すると変更なしで計画と実値を出し、曖昧デバイスでは非ゼロ終了する。実機修復はユーザーが明示実行したときのみ変更し、既定通信入力とVoiceMeeter値を再取得する。ブラウザのマイク切替失敗とWindows修復途中の失敗を注入し、部分成功・未実行・再取得不能が識別でき、検証済みへ昇格せず、再実行で成功項目を不要に再変更しないことを確認する。
- RAC-006: 実機でリモート参加者の声だけを入力し、ChatGPTが内容に応答し、全参加者が返答を聞ける。合格時だけ往復確認日時を保存する。ローカル本人の声による代替確認は禁止。
- RAC-007: `npm run build` と既存録画検証が通る。通常AI配信と明示開始した録画が動作し、追加API・診断・metadata・ログに音声内容が含まれない。ホスト・リモートそれぞれの再生経路と、録画のregistry・リモート・タブ音声経路を確認し、AI返答が各出力へ一度だけ入ることを検証する。
