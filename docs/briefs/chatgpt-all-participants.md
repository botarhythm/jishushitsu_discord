# 通常モードのChatGPT参加とワンクリック音声設定

- status: brief
- requested phase: Lake A2
- date: 2026-09-07

## ユーザーの依頼
「ChatGPTを参加させる機能を収録モードだけではなく、参加者すべてと対話できるようにする。そして今回確認が必要であったこの設定をワンクリックで実装できませんか？ $lake A2」

## 目的
通常の通話でもホストとリモート参加者が同じChatGPT音声セッションと対話できること。毎回WindowsとChatGPTのマイクを手で選び直す負担を減らすこと。

## 現在の根拠
- `components/RoomView.tsx` は `useAiParticipant({ enabled: aiEnabled && studioMode })` としており、収録モードを抜けるとAI接続が止まる。
- `lib/ai/chatgpt-input-mixer.ts` は人間のローカル・全リモートの音声を既に扱う。AI音声と画面共有音声を除外する安全境界を維持する。
- `components/AiWiringPlanPanel.tsx` はブラウザ内3項目の推奨一括適用を既に持つ。Windows側の2項目は案内のみ。
- 今回の実測では録音の既定の通信デバイスがC920で、変更後はVoicemeeter Out B1になった。さらにユーザーがChatGPT側のマイクが別デバイスであることを確認した。B1に信号があるだけではChatGPTの選択やリモートの声の到達を証明できない。

## 制約・非目標
- 既存のChatGPTデスクトップ音声と仮想オーディオ構成を基準とする。OpenAI API課金や認証切替は許可されていない。
- 通常モードでAI参加を明示表示し、送出停止・退出・再接続・部屋移動・複数ホストを要件化する。
- Windows設定をブラウザ単体で変更できると約束しない。ローカル補助ツールの要否、初回セットアップ、ChatGPT内のデバイス指定が変更可能かは調査して判断する。
- 録画・会話を勝手に開始したり、ChatGPTを強制終了したりしない。
- 別件の未コミット変更を保持する。

## 要件化前の確認点
- 全参加者とは「ホストがAIを有効にした同じルーム内の人間全員」を基本仮定とする。
- 一括設定ボタンで保証できる範囲と、権限・初回操作・音声疎通のユーザー確認が必要な範囲。
- AI状態のmetadataを収録レイアウトから分離する設計、信頼できる送信者と単一AI所有権。
- 本番公開は本機能の要件・検証がまとまってから扱う。直前のデプロイ許可はスポットライトを対象としていた。
