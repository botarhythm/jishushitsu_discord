# AI 参加者 (ChatGPT デスクトップ音声) セットアップガイド — Windows

収録モードに「人間2名 + ChatGPT音声」の3者ポッドキャスト収録を追加する機能の、
ホストPC（Windows 11 + Chrome）での音声ルーティング手順。

アプリは OS レベルの音声しか扱わない。OpenAI API・ChatGPT の認証情報は一切使わない。

## 構成は2種類ある

| 構成 | 必要なケーブル | ChatGPT が聞ける声 | 用途 |
|---|---|---|---|
| **A. 簡易構成** | VB-CABLE **1本**（標準パッケージ） | ホスト（自分）のみ | まずはこれ。相手の発言はホストが要約して伝える |
| **B. フル構成** | 仮想の道が**2本**（CABLE A+B 購入 or VoiceMeeter 追加） | ホスト + リモート参加者 | 3者が対等に会話する本番収録 |

まず A で動かし、必要になったら B へ上げるのが安全。

## 必要なもの（共通）

- ChatGPT デスクトップアプリ（音声モードが使えるプラン）
- [VB-Audio Virtual Cable](https://vb-audio.com/Cable/)
- **ヘッドホン必須**（スピーカーは自己ループの原因になるため禁止。特に構成 A では
  スピーカー使用が即座に「AIの声→スピーカー→物理マイク→ChatGPT入力」のループを作る）

# 最初にやること: ChatGPT 単体で音声会話できることを確認する

**仮想デバイスを一切使わない状態で、ChatGPT の音声モードが成立することを先に確認する。**
ここが成立していないまま配線を進めると、切り分け不能な状態で長時間溶かす（実際に溶かした）。

1. 音量ミキサーで ChatGPT の**出力・入力とも「既定」**に戻す
2. Windows の既定を 出力=ヘッドホン / 入力=物理マイク にする
3. ChatGPT を**完全に終了して再起動**（タスクトレイからも終了する）
4. 音声モードを開始し、マイクのミュートを解除して話しかける

会話が成立してから、はじめて仮想デバイスの配線に進む。

**それでも音声会話が成立しない場合は、アプリ別のサウンド設定をリセットする。**
設定 → システム → サウンド → 音量ミキサーの最下部にある
「すべてのアプリのサウンド デバイスとボリュームをおすすめの既定値にリセットする」
の**リセット**ボタンを押す。

アプリ別のデバイス割り当てを何度も変更していると壊れた状態になることがあり、
実機ではこれで復旧した（デバイス指定は正しいのに ChatGPT がマイクを
まったく拾わない状態だった）。

**注意**: リセットするとアプリ別の割り当てが全部消えるので、ChatGPT の
出力を `CABLE Input` にする設定もやり直しになる。

**ChatGPT アプリが複数入っている場合は要注意。** Windows のマイク権限一覧
（設定 → プライバシーとセキュリティ → マイク）に `ChatGPT` と `ChatGPT Classic`
のように複数並ぶことがある。片方で音声モードが動かない場合は**もう片方を試す**。

# 事前確認: 音声設定なしで機能を試す

音声ルーティングを触る前に、機能そのものの動作を確認できる。

1. 収録モードに入り、StudioBar の 🤖 ボタンでセットアップを開く
2. 「AI 音声ソース」のプルダウンで選ぶ代わりに、ブラウザのコンソールで
   デバイスIDに `fake` を設定する（開発用フック）。または一時的にコード側で
   `sourceDeviceId: 'fake'` を渡す
3. 880Hz のトーンが2秒ごとに鳴る疑似 AI 参加者が接続され、AI タイルが
   speaking ⇄ idle を繰り返す

ChatGPT も VB-CABLE も不要。タイル表示・録画混入・再接続の確認はこれで足りる。

# 構成 A: VB-CABLE 1本（今すぐ使える）

```
ChatGPT [出力 = CABLE Input] ──→ CABLE Output ──→ 本アプリ「AI 音声ソース」
                                                    ├→ 録画に混入
                                                    ├→ リモート参加者へ配信
                                                    └→ 自分のヘッドホンへモニタ再生

ChatGPT [入力 = マイク配列(物理マイク)] ←── 自分の声だけが届く
```

## 手順

1. **ヘッドホンを接続する**（スピーカー禁止）。
2. ChatGPT デスクトップを起動し、**音声モードで一度何か喋らせる**
   （音を鳴らさないと次の音量ミキサーに項目が出ない）。
3. タスクバーのスピーカーアイコンを**右クリック → 音量ミキサーを開く**
   （または 設定 → システム → サウンド → 音量ミキサー）。
4. 一覧の **ChatGPT** の行を展開し、
   - **出力デバイス** = `CABLE Input (VB-Audio Virtual Cable)`
   - **入力デバイス** = `マイク配列 (Realtek(R) Audio)` ※物理マイク
5. この時点で **ChatGPT の声は直接は聞こえなくなる**（ケーブルへ流れるため）。
   これは正常。アプリで AI 参加者を有効化すると、アプリがヘッドホンへ再生する。
6. 自習室の収録モード → 🤖 ボタンでセットアップを開き、
   - **AI 音声ソース** = `★ CABLE Output (VB-Audio Virtual Cable)`
   - **ChatGPT への送出先** = `使用しない (外部でルーティング済み)`
   - 下部のチェックボックス「外部ルーティングで ChatGPT の声が ChatGPT
     自身の入力に戻らないことを確認しました」に**チェック**
7. ChatGPT に何か喋らせ、**レベルメーターが振れる**ことを確認。
8. 「AI 参加者を有効にする」を押す。

## 構成 A の制約

- **ChatGPT にはリモート参加者の声が届かない。** 相手が話した内容は、ホストが
  「今〇〇さんがこう言ったんだけど」と口頭で要約して ChatGPT に伝える運用になる。
- 録画・配信には3者すべての声が入る（この制約は「ChatGPT の耳」だけの話）。

---

# 構成 B: 仮想の道を2本にする（フル3者会話）

構成 A の制約を外すには「ChatGPT の声を運ぶ道」と「人間の声を運ぶ道」の
**2本**が要る。標準の VB-CABLE パッケージには1本しか入っていないため、
2本目をどう用意するかで2通りある。

| | B-1: VB-CABLE A+B | B-2: VoiceMeeter |
|---|---|---|
| 費用 | 有料（最低 5€） | **無料**（寄付ウェア・機能制限なし） |
| 常駐 | 不要 | **必要**（ミキサー本体が動いていないと音が通らない） |
| 設定 | デバイスを選ぶだけ | ミキサー側のルーティング設定が1箇所要る |
| 失敗モード | 少ない | 「VoiceMeeter が落ちていた」が増える |

**本番の安定性を優先するなら B-1、まず無料で試すなら B-2。**
以下は B-2（VoiceMeeter）を先に説明する。B-1 は最後に併記。

## B-2: VoiceMeeter を2本目にする（無料）

### 確定構成（この設定で固定する）

実機検証で到達した最終形。**音量ミキサーのアプリ別設定は一切使わない**
（ChatGPT がアプリ別の入力設定を無視するうえ、行が増殖して管理不能になるため）。

**Windows のサウンド設定（`mmsys.cpl`）**

| タブ | 枠 | 設定するデバイス | 使うアプリ |
|---|---|---|---|
| 再生 | 既定のデバイス | ヘッドホン | ブラウザ・システム |
| 再生 | 既定の**通信**デバイス | ヘッドホン（通常どおり） | — ※ChatGPTの出力には効かない |
| 録音 | 既定のデバイス | `マイク配列`（物理マイク） | ブラウザ |
| 録音 | 既定の**通信**デバイス | `Voicemeeter Out B1` | ChatGPT（耳） |

**ChatGPT の出力だけは音量ミキサーで指定する**

実機検証の結果、**ChatGPT は入力（耳）は「既定の通信デバイス」を見るが、
出力（声）は通常の「既定のデバイス」を見る**ことが分かった。したがって出力だけは
アプリ別設定が必要になる。

1. ChatGPT に何か喋らせる（音を鳴らしていないと音量ミキサーに現れない）
2. 設定 → システム → サウンド → 音量ミキサー → `ChatGPT` の行を展開
3. **出力デバイス** = `CABLE Input (VB-Audio Virtual Cable)`
   - 行が複数あるときは**音量が 100 の行**（実際に鳴っている行）に設定する
   - 入力デバイスは**触らない**（無視されるため）

**VoiceMeeter**

- ハードウェア入力 IN1 / IN2: 未割当
- Virtual Input ストリップ: **B のみ点灯**（A は消灯）
- HARDWARE OUT A1: 何を割り当ててもよいが、A を消灯しているので音は流れない

**アプリ（自習室）の 🤖 セットアップ**

- ① AI 音声ソース: `CABLE Output`
- 通話マイク: `マイク配列`（「既定 -」が付かない方を名指しで選ぶ）
- ② ChatGPT への送出先: `Voicemeeter Input`

**音の流れ**

```
あなた ─┐
        ├→ アプリ → Voicemeeter Input → B1 → ChatGPT の耳
相手 ──┘

ChatGPT の声 → CABLE Input → CABLE Output → アプリ
                                              ├→ 録画
                                              ├→ 相手へ配信
                                              └→ あなたのヘッドホン
```

設定変更後は **ChatGPT を完全に終了して再起動**し、マイクボタンの
ツールチップが `Voicemeeter Out B1` になっていることを確認する。


VoiceMeeter は仮想ミキサーで、付属の仮想デバイス **VAIO** を仮想ケーブルとして
使える。既存の無印 VB-CABLE と組み合わせて2本の道を作る。

```
【ChatGPT の声】
ChatGPT [出力 = CABLE Input] → CABLE Output → アプリ「AI 音声ソース」

【人間の声】
アプリ「ChatGPT への送出先」= VoiceMeeter Input
  → VoiceMeeter の Virtual Input ストリップ → B1 バス
  → Voicemeeter Out B1 = ChatGPT [入力デバイス]
```

### 手順

1. **インストール後に PC を再起動**（オーディオドライバのため必須）。
2. 再起動したら、まず**既定の再生デバイスを確認して元に戻す**。
   VoiceMeeter はインストール時に自分を既定デバイスにしてしまうことがあり、
   そのままだと**普段の音が一切聞こえなくなる**。
   設定 → システム → サウンド → 出力 で **ヘッドホン/スピーカー（Realtek）** を
   選び直す。入力も物理マイクに戻す。
3. **VoiceMeeter を起動**し、次を設定する。
   - **ハードウェア入力（IN1 / IN2）は必ず「未割当」にする。**
     既に何か割り当たっていたら、ストリップ上部のデバイス名をクリック →
     **Remove Selection** で外す。
     - **特に `CABLE Output` を割り当ててはいけない。** これは ChatGPT の声を
       運ぶ経路で、B1 に流れると「ChatGPT の声 → ChatGPT の耳」の自己ループが
       そのまま成立する（本機能で最も避けたい事故）。
     - **物理マイク（マイク配列）も割り当てない。** 自分の声はアプリ側が
       LiveKit 経由でミックスして送るので二重になり、自己ループ検査も誤検知する。
   - **A1 は未割当のままでよい。** デバイスが無くても VoiceMeeter は
     「Internal Master CLOCK」でエンジンを回す（System settings に
     `OUT A1 Main Device  Status: ON` と出ていれば動いている）。
     この構成では A1 に音を流さないので、物理デバイスを掴ませる必要は無い。
     - 割り当てる場合は **MME (Multimedia)** + **スピーカー（Realtek）**。
       **KS (Kernel Streaming) は選ばないこと**（デバイスを排他的に掴み、
       Chrome が同じヘッドホンへ再生できなくなる＝相手の声が聞こえなくなる）。
     - **CABLE 系を A1 に選ばないこと。** ChatGPT の声を運ぶ経路を汚す。
   - 右側の **Virtual Input** ストリップ（"VoiceMeeter VAIO"）の
     **B1 だけを点灯**させる。**A1 は消灯**のままにする。
     - B1 点灯 = 人間の声が `Voicemeeter Out B1` に流れる（ChatGPT が聞ける）
     - A1 消灯 = その音が自分のヘッドホンに戻らない
       （点灯させると自分の声が遅れて聞こえ、相手の声も二重になる）
   - メニュー → System Settings / Options で
     **Preferred Main SampleRate = 48000 Hz** にする。
4. VoiceMeeter のメニューで **「System Tray」** と
   **「Run on Windows Startup」** を有効にする。
   以後は自動起動・トレイ常駐になり、普段は意識しなくてよくなる。
5. ChatGPT デスクトップを起動し、**音声モードで一度喋らせる**
   （音を鳴らさないと次の音量ミキサーに項目が出ない）。
6. **音量ミキサー**（タスクバーのスピーカーアイコンを右クリック →
   音量ミキサーを開く）で ChatGPT の行を展開し、
   - **出力デバイス** = `CABLE Input (VB-Audio Virtual Cable)`
   - **入力デバイス** — ここは効かないことがある（下記）

   **重要: ChatGPT は音量ミキサーのアプリ別入力設定を見ず、Windows の
   「既定の通信デバイス」を使う。** ChatGPT の音声モード画面でマイクボタンに
   カーソルを合わせると `Communications - <デバイス名>` と実際に使っている
   デバイスが出るので、そこで確認できる。

   したがって入力側は**既定の通信デバイスで指定する**:

   `mmsys.cpl` → 録音タブ → `Voicemeeter Out B1` を選択 →
   「既定値に設定」の ▼ → **「既定の通信デバイス」**

   録音デバイスの2つの枠を次のように使い分けることになる:

   | 枠 | 設定 | 使うアプリ |
   |---|---|---|
   | 既定のデバイス | `マイク配列`（物理マイク） | ブラウザ（自習室アプリ） |
   | 既定の通信デバイス | `Voicemeeter Out B1` | ChatGPT |

   設定後は **ChatGPT を再起動**してデバイスを掴み直させる。

   ここで実機でつまずいた点が3つある。

   - **ChatGPT Classic は複数の行に分かれて表示されることがある。**
     音量ミキサーはアプリ単位ではなく音声セッション単位の一覧で、ChatGPT は
     複数プロセスに分かれているため行が増える（閉じた直後のセッションが残る
     こともある）。どの行が実際に音を出すかは外から判別できない。
     その場合は**すべての行に同じ設定**を入れる（どの行が音声を鳴らすか
     分からないため）。
   - **各行の音量が 0〜1 やミュートになっていないか確認する。** 既定デバイスを
     切り替えた拍子に絞られることがあり、そのままだとケーブルにほとんど音が
     流れず、アプリのレベルメーターが振れない。
   - ⚠ **出力デバイスに `Voicemeeter Input` を選ばないこと。** そこは
     こちらの声を ChatGPT へ送るための経路で、入力デバイス
     (`Voicemeeter Out B1`) と組み合わさると ChatGPT が自分の声を
     聞き続ける暴走になる。ChatGPT の出力は必ず `CABLE Input`。
7. アプリ側の設定は下の「アプリ側の設定」へ。
   - AI 音声ソース = `CABLE Output`
   - ChatGPT への送出先 = `VoiceMeeter Input`

### VoiceMeeter 固有の注意

- **VoiceMeeter が起動していないと ChatGPT に声が届かない。** アプリ側からは
  検出できない（送り出すだけなので届いたか分からない）。収録前に必ず
  「自分の声に ChatGPT が反応するか」を実際に試す。
- B1 を消してしまうと同じく無音になる。ミキサー画面を触ったら B1 の点灯を確認。

## B-1: VB-CABLE A+B を買う（有料・最も安定）

[VB-Audio](https://vb-audio.com/Cable/) の
**「Donate for download VB-Cable A+B for Windows」**（C+D は不要）。
寄付ウェアだが最低額があり、0円の選択肢は無い。

1. 金額を選ぶ画面を通るとダウンロードリンクが出る（`VBCABLE_A_B_Driver_Pack45.zip`）。
2. zip を**展開してから** `VBCable_AB_PackSetup.exe` を**右クリック →
   管理者として実行**。
3. **PC を再起動**。
4. `CABLE-A Input/Output`・`CABLE-B Input/Output` が増える。
5. 音量ミキサーで ChatGPT の **出力 = CABLE-A Input / 入力 = CABLE-B Output**。
6. アプリ側は AI 音声ソース = `CABLE-A Output` / 送出先 = `CABLE-B Input`。

常駐アプリが不要なぶん失敗モードが少ない。

## アプリ側の設定（構成 B 共通）

B-1 / B-2 のどちらで2本目を用意したかによって、選ぶデバイス名だけが変わる。

| アプリの設定項目 | B-2 (VoiceMeeter) | B-1 (CABLE A+B) |
|---|---|---|
| AI 音声ソース | `CABLE Output` | `CABLE-A Output` |
| ChatGPT への送出先 | `VoiceMeeter Input` | `CABLE-B Input` |

### 手順

1. **ヘッドホンを接続する**（スピーカー禁止）。
2. Windows サウンド設定で **使うデバイスを 48000 Hz に統一**
   （サンプルレート不一致は音割れ・ノイズの原因）。
   設定 → システム → サウンド → 各デバイス → 「形式」を 48000 Hz に。
3. 自習室の収録モードに入り、StudioBar の 🤖 ボタンからセットアップを開く。
4. 「**AI 音声ソース**」を上の表のとおり選択。ChatGPT に何か話させ、
   **レベルメーターが反応する**ことを確認。ここが動かなければ先へ進んでも無駄。
5. 「**ChatGPT への送出先**」を上の表のとおり選択。
6. **プリフライト（自己ループ検査）を実行**。
   この検査中はまだ ChatGPT にこちらの声は届かないので、**ChatGPT にテキストで
   話しかけて音声で返答させながら**ボタンを押す。
   「AI の声が送出先に漏れていない」ことが確認されると合格。
7. 「**AI 参加者を有効にする**」を押す。ステージ下段に AI タイルが表示され、
   ChatGPT の発話でアバターが speaking 状態になる。
   **ここで初めて ChatGPT にこちらの声が届くようになる。**
8. **参加中のメンバーにページの再読み込みを依頼**（AI タイルは新しい画面でのみ表示される）。
9. 録画開始。**AI の有効化は必ず録画開始前に行う**（録画中の有効化は不可）。

### 2回目以降はワンクリック

一度この手順を通すと**その配線を記憶する**ため、次回からは講師ダッシュボードの
**「🤖 ChatGPTつきで収録開始」**を押すだけで、収録モード投入と AI 参加者の
呼び出しまで一気に完了する。

デバイスを変更した場合や、記憶したデバイスが見つからない場合は自動的に
セットアップ画面が開き、再度この手順を通すことになる（自己ループの危険は
配線に紐づくため、配線が変わったら必ず再確認する設計）。

## トラブルシューティング

- **レベルメーターが動かない**: ChatGPT の出力デバイス設定がリセットされていないか確認
  （アプリ更新で既定デバイスに戻ることがある）。
- **「音声解析が停止中」表示**: 画面のどこかをクリックすると解除される（ブラウザの
  autoplay 制限）。
- **AI タイルが「⚠ 音声ソース切断」**: CABLE デバイスが無効化された。デバイスを戻して
  セットアップ画面の「再接続」を押す。**録画は途切れず継続している。**
- **遅延が大きい/音質が悪い**: 48kHz 統一を確認（VoiceMeeter 側の
  Preferred Main SampleRate も 48000 に）。
- **自分の声が二重に録れる**: 「AI 音声ソース」に物理マイクを選んでいないか確認
  （セットアップ画面に警告が出る）。
- **音量ミキサーに ChatGPT が出てこない**: そのアプリが音を鳴らしている間しか一覧に
  出ない。音声モードで喋らせた状態で開く。
- **ChatGPT が自分の声に反応し続ける（暴走）**: スピーカーを使っていないか確認。
  構成 A ではスピーカー使用が直ちに自己ループになる。

### ChatGPT アプリがマイクをまったく拾わない

Windows の録音デバイスには**「既定のデバイス」と「既定の通信デバイス」の2枠**があり、
通話アプリは後者を使うことがある。設定 → システム → サウンド → 入力 の一覧で、
各デバイスの下に「既定のデバイス」「既定の通信デバイス」と表示される。

VoiceMeeter を入れると通信デバイス側が `Voicemeeter Out B3` などに
奪われていることがある。B3 は VoiceMeeter Standard には存在しないバスなので
無音になり、ChatGPT は何も聞こえない。

**対処**: `マイク配列` を「既定のデバイス」と「既定の通信デバイス」の**両方**に設定する。
`mmsys.cpl` → 録音タブ → 対象デバイスを右クリック → 「既定のデバイスとして設定」と
「既定の通信デバイスとして設定」を両方実行するのが確実。

**注意**: Windows の既定を変えても、すでに開いているブラウザのマイクは切り替わらない。
変更後はブラウザを再読み込みすること。

### ChatGPT がハウリングする / 自分の声だけ届かない

**通話マイクが「ステレオ ミキサー (Stereo Mix)」になっていないか確認する。**
セットアップ画面の「送出経路:」の行に、アプリが使っているマイク名が出る。

ステレオミキサーは物理マイクではなく、**スピーカーに出ている音をそのまま録る**装置。
これをマイクにすると次の2つが同時に起きる。

- アプリが再生している AI の声を拾って ChatGPT へ送り返す → **ハウリング**
- 自分の声は一切入らない（再生音しか録らないため）→ **ChatGPT に届かない**

名前に「Realtek」が入るので物理マイクと紛らわしいが別物。Windows の既定の
録音デバイスを `マイク配列 (Realtek(R) Audio)` などの**実際のマイク**に変更する
（設定 → システム → サウンド → 入力）。

アプリ側は検出すると送出を自動停止し、警告を表示する。

### ChatGPT がこちらの声にまったく反応しない

まず**切り分け**る。音量ミキサーで ChatGPT の入力デバイスを一時的に
`マイク配列 (Realtek)` など**物理マイク**に変えて話しかける。

- **それでも反応しない** → ChatGPT 側の問題。配線は無関係。下の順に確認する。
- **反応する** → 配線側の問題。アプリの「送出モニタ」で声が届いているか見る。

ChatGPT 側の確認（上から順に）:

1. **Windows のマイク権限**: 設定 → プライバシーとセキュリティ → マイク →
   「マイクへのアクセス」と「**デスクトップアプリがマイクにアクセスできるように
   する**」の両方がオン。ここがオフだと何を指定しても聞こえない。
2. **ChatGPT を完全に終了して再起動**。デバイスの割り当てを起動時に読み込む
   作りのため、起動後に変更しても反映されないことがある。タスクトレイに常駐
   していることがあるので、そちらからも終了する。
3. **音声モード画面のマイクボタンがミュートになっていないか**（斜線入りアイコン）。
4. **マイク自体が Windows で動いているか**: 設定 → システム → サウンド → 入力 →
   対象デバイスの音量バーが話すと振れるか。振れなければマイク側の問題。

### VoiceMeeter 構成でのつまずき

- **PC の音が急に一切聞こえなくなった**: VoiceMeeter が既定の再生デバイスを
  奪っている。設定 → システム → サウンド → 出力 でヘッドホンを選び直す。
- **ChatGPT がこちらの声にまったく反応しない**: 次の順に確認する。
  1. VoiceMeeter 本体が起動しているか（トレイ常駐しているか）
  2. Virtual Input ストリップの **B1 が点灯**しているか
  3. A1 に出力デバイスが割り当たっているか（未割当だとエンジンが回らない）
  4. ChatGPT の入力デバイスが `Voicemeeter Out B1` になっているか
- **自分の声が遅れて自分に聞こえる / 相手の声が二重になる**:
  Virtual Input ストリップの **A1 が点灯している**。消灯させる。
- **自己ループ検査が誤って不合格になる / ChatGPT が自分の声に暴走する**:
  VoiceMeeter のハードウェア入力（IN1 / IN2）に何か割り当たっていないか確認する。
  System settings 画面で IN1 / IN2 が `- none -` 以外なら要修正。
  - `CABLE Output` が割り当たっている場合は**即座に外す**。ChatGPT の声が
    そのまま ChatGPT の耳へ戻る自己ループになる。
  - 物理マイクが割り当たっている場合も外す（B1 に混ざり漏れとして検出される）。
