## 確定した主要な学び

1. **設定消失の根因**: スキーマ版数なしの optional boolean (「無いから既定値 true」) ×
   古いスナップショット全体保存。修正は v2 封筒 + patch 書き込み一本化 + Web Locks 直列化。
2. **本日のハウリングの根因**: チェックボックス2つが effect の依存配列に無く、
   AI 有効化後の変更が稼働経路に反映されなかった。
3. **音響検査の鉄則**: トーンは「鳴り始めを await してから」測る。失敗は全て fail に
   伝播させる (鳴っていないのに合格が最悪)。「音があった」は「本人の声」ではない —
   包絡線相関 + マイク実測の前提条件で確かめ、確かめられないときは設定を変えない。
4. **検証済みの持ち方**: boolean ではなく「どの配線を検証したか」の指紋。
   有効化時に現在の配線と照合すれば、並行変更に対してイベント順序へ依存しない。

## 実機GO条件 (コード判定とは別。次回の実機検証で確認)

- [ ] VoiceMeeter経由・アプリ経由の両構成で、相関判定が期待どおり sendLocalMic を切り替える
- [ ] アプリ経由判定が不合格のとき、ChatGPT 入力へマイクが混入し続けない
- [ ] AI音声ソースの仮想デバイスを、常時レベルメーターと検査プローブが同時に開ける
  (ドライバによっては監視入力の複数 capture が失敗しうる)
- [ ] 録画中に全検査・試聴が拒否され、録画 WebM にテストトーンが混入しない
- [ ] トーン出力先を無効化/取り違えた場合に、自己ループ検査が明示的に失敗する
