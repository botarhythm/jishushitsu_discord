## 第2巡の付帯条件（実装時に満たすこと）

1. **[High] `manualConfirm` だけでは安全ゲートとして不足。** ヘッドホン接続／ChatGPTの実入力
   デバイス確認／AI発声中に自声へ連続反応しないことの数秒確認、をセットで運用ゲート化し、
   その結果を manualConfirm に記録する。
   **旧 localStorage 設定は必ず「未検証」に落とす**（`sinkDeviceId === null` だけで
   A へ自動移行させると、過去のB設定や未検証設定を誤って通す）。
2. **[Medium] 2モード（`desktop-simple` / `desktop-full`）だけ型に置く判断は正しい。**
   realtime はスパイク着手時に追加する。設定には `mode` と schema version を持たせ、
   旧設定は安全側（検証済み指紋は破棄・手動確認を再要求・不明値はセットアップを開く）に倒す。
3. **[Medium] サーバー参加者方式の先回り実装は不要。** ただし `ownerIdentity` の仕様コメントは
   今のうちに「このAIトラックを publish した participant の identity」と定義し直す
   （「ホスト」と書いていると将来サーバーAIで意味が破綻する）。
4. **[High] Cのスパイクには Realtime セッションの60分上限と障害復帰を必須評価項目に入れる。**
   時間到達時の切断・再接続・会話文脈・録画/publish継続。認証エンドポイントとAPI障害表示も
   最小範囲に含める。
5. **[Low] 「ChatGPT Webタブの音声キャプチャ」は却下案として設計メモに記録する。**
